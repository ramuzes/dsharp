A role template is exactly what you would otherwise type to the lead agent: a name, a one-line description, the standing instruction (responsibility boundary and main goal), and an optional model.

From the composer's "+" menu you pick a template, optionally override the model and add a first task, and confirm. The plugin runs the `/roster` command, which the transcript records the way it records `/compact` — a compact command entry with its outcome, no message from you and no turn of the lead. The member is created with the template's standing prompt (frozen, never rewritten) as its role and **stands by**: it is told explicitly that nothing inherited from your session is an assignment and that work will arrive through messages or the shared task board. A first task typed in the dialog becomes its first assignment, and its result is then reported back to the lead. `/roster <template name or id>` can also be typed directly. The lead agent can create members itself with the `roster_spawn` tool, under the same rules.

Manage templates in **Settings > Agent roster**: create, edit, delete, and set each template's default model (through the same model picker the rest of the harness uses). The `roster_template_save` / `roster_template_list` tools let the lead agent distill the role you have just been using into a template from inside the conversation; the `exposeAgentTools` option hides those two authoring tools when a deployment wants the model to stay out of the roster.

The member's model and reasoning effort can be overridden for a single spawn from the same dialog. The picker starts from the template's default; choosing "inherit the session model" clears it for this member. The template itself is never edited; from the dialog your choice is handed to the host directly and never passes through a model.

Members are ordinary subagents: they appear in the host's Subagents panel and in `list_agents`, and nothing about them is rendered by this plugin.
