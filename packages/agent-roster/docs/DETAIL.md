A role template is exactly what you would otherwise type to the lead agent: a name, a one-line description, the standing instruction (responsibility boundary and main goal), and an optional model.

Creation is agent-driven. From the composer's "+" menu you pick a template, see the exact instruction that will be sent, optionally add this session's task, and confirm. The plugin injects that instruction into the current conversation as a user message, so the lead agent runs its normal loop — reading the session's context and filling in the task — and calls the `roster_spawn` tool. That tool performs the deterministic part: it resolves the caller's subagent tree root, allocates a free member name, and spawns the member with the template's standing prompt (frozen, never rewritten) and its model. The Remote surface is template CRUD only.

Manage templates in **Settings > Agent roster**: create, edit, delete, and set each template's default model (through the same model picker the rest of the harness uses). The `roster_template_save` / `roster_template_list` tools let the lead agent distill the role you have just been using into a template from inside the conversation; the `exposeAgentTools` option hides those two authoring tools when a deployment wants the model to stay out of the roster.

Members are ordinary subagents: they appear in the host's Subagents panel and in `list_agents`, and nothing about them is rendered by this plugin.
