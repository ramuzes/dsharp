角色模板就是你本来要对 leader 说的那句话：名称、一句话描述、常驻指令（职责边界与主要目标），以及可选的模型。

“+”菜单里选一个模板，可选地覆盖模型、填写首个任务，然后确认。插件运行 `/roster` 命令，会话记录对它的呈现方式与 `/compact` 相同——一条紧凑的命令记录及其结果，对话里不会出现你“说”的话，也不占用 lead 的一轮。成员以模板的常驻指令（冻结、不被改写）作为角色被创建，并**待命**：它会被明确告知，从你的会话继承来的任何内容都不是给它的指派，工作会通过消息或共享任务板送达。在弹窗里填写的首个任务会成为它的第一项指派，完成后结果回报给 lead。`/roster <模板名或 id>` 也可以直接输入。lead agent 自己也能用 `roster_spawn` 工具创建成员，规则相同。

在 **设置 > Agent roster** 管理模板：新建、编辑、删除，并为每个模板设置默认模型（使用与 harness 其它地方一致的模型选取器）。`roster_template_save` / `roster_template_list` 工具让 lead agent 在对话中把刚用过的角色沉淀成模板；`exposeAgentTools` 选项可隐藏这两个写作工具，供不希望模型接触花名册的部署使用。

成员的模型与推理力度可以在同一个弹窗里针对本次生成单独覆盖：选取器以模板默认值为起点，选“继承当前会话模型”则这位成员不再使用模板默认。模板本身不会被修改；从弹窗做出的选择直接交给宿主，不经过任何模型。

成员就是普通的子代理：出现在宿主的 Subagents 面板与 `list_agents` 中，本插件不渲染任何成员列表。
