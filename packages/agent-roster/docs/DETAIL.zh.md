角色模板就是你本来要对 leader 说的那句话：名称、一句话描述、常驻指令（职责边界与主要目标），以及可选的模型。

创建成员是 agent 驱动的。“+”菜单里选一个模板、查看将要发送的完整指令、可选填本次任务，然后确认。插件把这条指令作为用户消息注入当前会话，于是 lead agent 正常跑它自己的 loop——读取会话上下文、补全任务——并调用 `roster_spawn` 工具。该工具负责确定性的部分：解析调用者所属子代理树的根、分配一个空闲的成员名、用模板的常驻指令（冻结、不被改写）与模型创建成员。Remote 接口只有模板 CRUD。

在 **设置 > Agent roster** 管理模板：新建、编辑、删除，并为每个模板设置默认模型（使用与 harness 其它地方一致的模型选取器）。`roster_template_save` / `roster_template_list` 工具让 lead agent 在对话中把刚用过的角色沉淀成模板；`exposeAgentTools` 选项可隐藏这两个写作工具，供不希望模型接触花名册的部署使用。

成员的模型与推理力度可以在同一个弹窗里针对本次生成单独覆盖：选取器以模板默认值为起点，选“继承当前会话模型”则这位成员不再使用模板默认。模板本身不会被修改；指令里会明确写出所选模型，因此它能原样传到 `roster_spawn`。

成员就是普通的子代理：出现在宿主的 Subagents 面板与 `list_agents` 中，本插件不渲染任何成员列表。
