# 复盘:feishu-gateway 开发全程踩坑归因(5-Why)

> 范围:`feat/feishu-bot-plugin` 分支从零到 gateway-as-browser 重构的全部真实故障。
> 方法:四组独立 5-why 分析(Remote 调用契约 / 架构弯路 / 接口形状假设 / 测试有效性与运维),本文为其汇总与去重。
> 用途:防再发清单的依据,新插件/新平台接入时的 checklist 来源。

## 一、四组根因一览

| 组 | 表层症状 | 链尾根因(一句话) |
|---|---|---|
| A. Remote 调用契约 | signal 未传必炸、三种调用形状、扁平/嵌套字段猜错 | 调用契约只存在于宿主 TS 源码:编译期传导、文档传导、运行时校验、严格 fake **四道防线同时缺席** |
| B. 架构弯路 | {{model}} 变量、空心 Agent(36 tool-removal)、flock 锁冲突、手搓排队/目录 | **入手点由"最先看到什么"(可见性)而非"最高层抽象在哪"(层级)决定**;"服务端插件=自己编排"的假设未检验 |
| C. 接口形状假设 | SDK 事件被静默过滤、调用不存在的成员、数据源选错、inject 静默 INACTIVE、schema 库用错 | **用猜测/类比填充未知接口** + **静默失败比报错更危险**(框架把失败建模为合法状态) |
| D. 测试有效性与运维 | fake 宽容致全绿线上炸、fire-and-forget 竞态、pkill 自杀/误杀、EROFS/端口/状态文件互踩 | 测试验证的是 **mock 的世界而非真实世界**;**"单实例、可写 HOME、手动管进程"的隐式假设**在多实例+沙箱场景全部失效 |

## 二、跨组共同根因(去重后的四条主干)

1. **契约不可见**:JS 插件消费 TS 宿主,必传性/形状/参数名全靠读实现源码;HTTP 网关还把形参名(含 `_request`)反射成对外协议。
2. **层错位**:能拿到底层服务(agents/llm)≠应该直接用;官方客户端(Web GUI、DSH Mobile)只做协议翻译,是平台作者给出的正确答案,却没有先抄。
3. **静默失败**:事件被过滤无计数、undefined 穿透、inject 拼错=永久等待、嵌套传参 fail-open——每条故障路径都有吞错机制,错误延迟数小时才显形。
4. **mock 世界 ≠ 真实世界**:fake 比真实接口宽容(签名、返回形状)、副作用无确定性完成信号、宿主把插件 unhandled rejection 升级为 fatal(架构放大器)。

## 三、防再发清单(按性价比排序,✅=已在本仓库落地)

### 立即(零成本约定)

1. ✅ **fake 必须复刻真实签名的严格性**:必填参数(如 signal)缺失即抛、返回形状与真实 API 一致({items} 不是裸数组);禁止手写宽容 fake。(signal 坑已按此修复,tests/driver.spec.js 有裸解引用 fake)
2. **未知接口先 grep 宿主/SDK 源码确认存在才准用**——`lastUserSource()`、`ApprovalRequestEvent.prompt` 这类"不存在的成员"当场可灭。
3. **外部 payload 先 JSON.stringify 全量入事件日志再写解析**(Lark SDK 扁平化坑的通用解)。
4. **禁止 `pkill -f` 模式杀进程**:按 pid 文件精确停止;命令行匹配至少用 `[p]attern` 防自匹配;**永远不用能同时匹配多实例的模式**。
5. **长驻进程一律用托管后台任务**,不用 shell `&`/nohup(随会话退出被清,且无法观测)。

### 短期(本仓库可做)

6. **异步副作用提供可等待的完成信号**(或统一 flush 点),测试禁止瞬时快照断言 fire-and-forget 路径(status 竞态坑)。
7. **对"静默过滤"零容忍**:transport 的 filtered:* 分支加计数,持续 100% 过滤率时主动告警(事件日志已有雏形,补阈值检查)。
8. **状态/事件文件按 profile/appId 命名**(audit P3-6:双宿主互踩)。
9. **接入新平台的强制第一步:逆向官方客户端调用面**(DSH Mobile 的 PROTOCOL.md 就是现成范本);自顶向下找入口(controller→服务→原语),底层原语只作兜底并记录理由。
10. **"手写框架级代码"触发自检**:发现自己写 setup 回调、生命周期恢复、排队语义、目录拼装时,先问"宿主是否已有此能力"。

### 中期(需要基建/上游)

11. **调用点速查表→由 d.ts 自动生成**:方法 × 进程内形状 × HTTP args 形状 × 必填参数 × signal 约定;先手工一页止血,再 CI 生成防漂移。
12. **数据边界运行时校验**(zod)跨进程返回值,错误 fail-fast 而非静默失效。
13. **真实链路最小冒烟**:fake 单测之外保留一条真实依赖集成测试/启动自检(fiber ACTIVE 断言、持久化写读回环)。
14. **上游反馈**:宿主统一 signal 解引用风格(`signal?.` 或框架注入)、unhandled rejection 不默认升级 fatal、Remote 入口 schema 校验、外部协议显式 schema(形参名不再是对外协议)。

## 四、量化信号(复盘校验用)

- **可删代码量**:gateway-as-browser 重构删除远多于新增 → 原方案站错层的量化证据。换方案时以此校验。
- **错误显形延迟**:从引入到暴露的时间(静默过滤数小时 vs TypeError 即时)——延迟越长,防御成本越高,越值得在边界加自检。

## 五、一句话收束

> 官方客户端就是平台作者给出的正确答案——接入任何平台,先抄答案,再谈创新;
> 而测试验证的必须是真实世界的契约,不是 mock 世界的宽容。
